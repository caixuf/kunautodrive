# 策略生成硬约束 Prompt 模板

> 用途:M6 策略生成器自动拼接到 LLM 请求尾部;人工让 AI 写策略时也可直接复制本文件正文(从「编写量化策略代码」起)粘贴。
> 配套治理:docs/KUNQUANT_ROADMAP.md §2-G。本文件只解决关卡 1(约束声明),关卡 2/3(引擎断言 + 数据平移测试)在代码与 CI 中强制执行,AI 口头自检不可信。

---

编写量化策略代码,严格遵守以下硬性约束,违反任意一条即视为严重 bug,写完代码后必须逐条自查回答文末四个问题,如实写明策略缺陷,禁止美化回测预期。只输出工程可运行代码。

## 一、【绝对禁止,违反视为代码 bug】

1. **严禁未来函数**:计算任何指标、交易信号,只能使用当前 K 线及之前时刻的数据,禁止引用未来 K 线的 open/high/low/close/volume;不允许用未来收盘价修正当前 bar 信号。要求代码内以注释标注每一处数据取用的时间边界。
2. **禁止过拟合魔法参数**:不允许自动遍历大量参数寻优来适配历史行情;禁止直接给出经过回测打磨过的神奇参数。参数给行业常用默认值即可,参数优化留给人手动完成。
3. **禁止忽略交易成本**:回测逻辑必须内置滑点与手续费,不允许默认 0 滑点 0 手续费;滑点必须取合理保守值,禁止写死 0。
4. **禁止理想化成交假设**:信号在 K 线内部触发的,不允许默认以信号价成交;涨跌停、停牌标的直接禁止开仓。
5. **禁止无限扛单**:任何策略不允许不带止损;不允许亏损后加仓摊薄成本的默认逻辑,除非用户明确主动要求开启。
6. **禁止美化回测**:不允许过滤掉历史上亏损的时间段、剔除坏行情,完整全量数据必须跑完。

## 二、【强制必须实现,缺一项即不合格】

1. **基础风控模块**:单标的仓位上限、账户总最大回撤监控;回撤触发阈值到达后必须有降仓/停止交易逻辑。
2. **异常处理**:行情缺失、NaN、空数据、接口异常必须处理,不允许直接崩溃。
3. **完整日志**:每一笔信号的时间、触发条件、成交价格、仓位,全部打印记录。
4. **回测与实盘代码分离**:回测专用逻辑不得泄漏到实盘分支。
5. **完整报告**:不允许只打印收益率,必须输出:最大回撤、盈亏比、胜率、最大连续亏损月份。

## 三、【输出自检,写完代码后逐条回答】

1. 检查代码中哪里有可能引入未来函数?逐一说明每处数据取用的时间范围。
2. 当前滑点、手续费设置的具体数值是多少?
3. 止损与风控逻辑具体在哪几行?
4. 该策略在哪一类行情下会明显亏钱?如实说明策略短板,禁止只讲优点。

> 注意:以上自检仅为第一道关卡。系统会另外执行数据平移测试(每根 bar 数据延后一根可见,绩效显著变化即判作弊)与引擎断言(成交价越界/零成本/无止损直接拒载),并通过后才进入人工 review。
