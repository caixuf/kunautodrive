**这一线的判据（都不依赖涌现量）**：
- Rule5 **目标跳变**（`lateral_target_chatter`）：planning `target_lane_offset` 不在车道中心间阶跃（机动帧豁免）
- Rule6 **目标骑线**（`lateral_target_offgrid`）：target 必须落在合法车道中心（相位 = w/2 或 0），**含机动帧** —— 掉头段每帧只漂 0.07~1.45m，Rule5 结构上看不见，所以两条不冗余
- D2-10 `max_lane_offset_m = 1.65`：`planning/debug.lane_match_offset`（Prefer）→ `localization/lane_match` 回退；**匹配失效帧不计**（A11）

## 3. 已知未修 / 未达标（交付时请知悉）

1. **D2-10「12/12 PASS」未达标，且不是横向的问题** —— 实测 4 场景 × 3 repeats（`scenario_regression.py
   --d2-10-scenes --repeats 3`，即 enforce 打开）：
   - **横向判据 12/12 全达标**：`max_abs_llt_offset_m` 逐次为
     straight 0.932 / 1.082 / 1.095、curve 0.070 / 0.103 / 0.108、
     urban 1.192 / 1.153 / 1.170、city 0.152 / 0.156 / 0.153 —— **最差 1.192 m**，阈值 1.65 m。
   - **总判定 11/12 PASS**：唯一 FAIL 是 `straight_road` 第 2 次重复的
     `comfort: jerk max 16.1 m/s³ exceeds 15.0`。同一二进制同一场景三次跑出
     9.6 / 12.4 / 16.1，只有一次越线。
   - 根因：jerk 取**整段逐帧加速度差分的最大值**（极值统计），单帧尖峰独自决定判定；
     旁证：仓库基线 `tests/baseline/straight_road.json` 里该值是 **1293 m/s³**（物理上不可能）。
     → 已登记 `docs/FAILURE_MODES.md` §5。修法方向：改分位数（`jerk_p95` 已有独立门禁）
     或尖峰去噪后再取极值。**这条不挡横向交付，只挡 D2-10 的"证书"**。
2. **Lanelet2 submodule 未 init**（`third_party/lanelet2/` 只有占位 README）：插件 configure 会打两条
   WARNING，flowsim 的**真 lanelet::Id 路径编译期关闭**、退回合成 ID（`llt_id = road_id*1000 + lane_id + 500`），
   仿真行为正确但"真 ID"这一步在本机没被验证。要开：`git submodule update --init third_party/lanelet2`
   （上游依赖 Eigen/Boost/pugixml/Glibmm，CI 集成慢）。
3. **`monitor_server.c` 缓存 JSON 坏体未定位**（`FAILURE_MODES.md` §4 最后一行）：管线退出后只留 flowmond
