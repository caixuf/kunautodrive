# 后记 · 技术展望：一张自动驾驶的前沿地图

> **本章解决什么问题**：前面九卷讲的是「现在」。本卷把镜头拉远——把近年自动驾驶
> 最有分量的技术方向铺成一张地图，逐项讲清「它解决什么、学术界怎么做的、和我们项目
> 的哪块骨架能接上、接上要付出什么代价」。
>
> **诚实边界**：凡标注「已有骨架」的是项目里真实存在的接口；其余是**基于公开研究的
> 前瞻推演**，供思考演进方向，不代表项目承诺实现，也不代表这些技术已经成熟可用。
> 本章更想传达的是一个判断框架，而不是一份技术清单。

## 0. 一张地图：从五个轴看未来

自动驾驶的技术演进可以归纳成五根轴。任何一篇论文、任何一个新框架，都落在某个轴的
某个位置：

| 轴 | 核心问题 | 代表方向 |
|----|---------|---------|
| **决策轴** | 谁来决定「做什么」 | 模块化 / 端到端 / 大模型决策 / 离线 RL |
| **感知轴** | 车「看见」什么 | 目标检测 → BEV → **占据网络（Occupancy）** |
| **世界轴** | 车「想象」什么 | 确定性物理 / 生成式世界模型 / 神经重建仿真 |
| **数据轴** | 车「学」什么、学谁的 | 行为克隆 / DAgger / 数据引擎 / 主动学习 |
| **部署轴** | 怎么安全落地 | sim2real / 影子模式 / 运行时安全 / 车端推理优化 |

下面五节各占一轴，最后一节收束到「检验标准」。

---

## 1. 决策轴：从模块化到端到端，再到"会推理的车"

### 1.1 模块化：我们正在做的

本书卷三的架构（感知 → 行为 → 规划 → 控制 → 安全）就是**模块化**路线。它的优势
在全书反复出现：每块可独立验证、职责铁律守住边界、故障可定位。它的天花板也诚实——
每个模块只看到上游的「摘要」（比如行为层只看到障碍物列表，看不到原始点云），信息在
传递中丢失。

### 1.2 端到端：一张网把感知到动作学出来

端到端（End-to-End）用一个大网络吃原始输入（图像/点云 + 指令）直接出动作。它消灭
了「模块间信息摘要丢失」，但也把「可解释性」和「故障定位」一起消灭了——出了事故，
你无法指着某个中间层说「它错了」。

**与本项目的关系**：项目的态度不是「二选一」，而是「**混合**」——端到端模型作为
影子角色先在 `inference/trajectory` 旁路对比，promote 门禁评估通过才晋级；即使晋级，
`planning → control → safety_control` 安全链也不被绕过。这其实对应了业界一个成熟
共识：**「端到端模型给意图，模块化系统给保障」**。模型负责「聪明」，铁律负责「不出
事」。VLA 正是端到端的一种具体形态（卷七骨架 `ai_framework.py` 的 `VLAAdapter` 已留好
接口）。

### 1.3 大语言模型进驾驶：不是让它开车，是让它"想"

2023 年后「LLM 做自动驾驶」成为显学。但一个清醒的判断是：**LLM 不适合做低时延的
连续控制**——它太慢、太贵、输出不保证可微。它真正有价值的位置在**高层**：

- **路线级决策**：「前方拥堵，改走备选路线」这种分钟级、需要常识/语义理解的决定；
- **意图解析**：把「第二个路口右转」「停在那个蓝色车前」这类自然语言指令翻译成
  行为层的目标；
- **场景解释**：把事故录像描述成自然语言报告，供评估器/追溯用。

**与本项目的关系**：行为层（8 状态 FSM）的 `CRUISE / FOLLOW / U_TURN / YIELD` 这些
离散状态，天然是 LLM 输出的「词汇表」——LLM 产出一个状态，模块化链路负责执行。
这也解释了为什么行为层被设计成「只决定做什么」：**离散状态是机器和语言模型都能
理解的中间表示**。

### 1.4 离线 RL 与决策 Transformer：不靠专家也能学

行为克隆（卷七现状）的问题是：学的是「老师的样子」，老师不会的它也不会。离线强化
学习（Offline RL）从**固定数据集**学出一个策略，能学到数据里隐含的「更好」；决策
Transformer（DT）把 RL 问题重写成「给定回报，预测动作序列」的序列建模问题。

**与本项目的关系**：`tools/train_e2e/temporal_train.py` 的时序窗口已经是「序列建模」
的雏形；卷七记录的 DAgger 自我对弈是「分布修正」的轻量版。Offline RL 是更重、回报
更难标定的路线，但它的回报函数（`demo_evaluator` 的碰撞/偏航/停滞评分！）其实已经
在 `/tmp/flow_topology.json` 里了——**评估器分数本身就是现成的 RL 回报信号**，这是
一条很自然的衔接点。

## 2. 感知轴：从"数盒子"到"填空间"

### 2.1 目标检测的天花板

项目当前感知 = DBSCAN 点云聚类 + RANSAC 去地面（卷三）。这是经典的「数盒子」范式：
把世界压缩成「几个障碍物 + 框」。它有两个结构性问题：

1. **漏检即灾难**：没被聚类出来的障碍物根本不存在于下游——感知是唯一「漏了不会
   报错」的环节；
2. **类别有限**：只有「是车/是行人」的类别，表达不了「悬空的电线」「路面的坑」。

### 2.2 BEV：把传感器揉到一张俯视图

Bird's Eye View（鸟瞰视角）是 2021 年后的感知主流：把多相机/雷达的特征投影到统一
的俯视 BEV 网格，后续规划直接吃 BEV。它解决了「传感器坐标系不一致」的问题。

### 2.3 占据网络（Occupancy）：感知的下一代

占据网络把「检测框」换成「体素网格的占据概率」——**不问「这里是不是一辆车」，而问
「这个 0.5m 立方体被占用了吗」**。它的三个革命性好处：

- **任意形状**：车、人、电线、悬空障碍都能表达（不需要类别）；
- **几何诚实**：预测的是空间占用，天然可做碰撞检测；
- **不确定性**：每个体素有概率，直接喂给规划做「概率碰撞」。

**与本项目的关系**：这是感知轴里最值得关注的方向，因为我们的下游（ST 图 + DP 速度
规划）**已经是时空网格**。把 `st_graph.c` 的「动态障碍墙」从「检测框的 0/1 占用」换成
「占据网络的概率场」，就是把规划升级为**概率规划**——这是感知和规划两个轴的交汇点，
改动量集中在 ST 图的代价函数。

## 3. 世界轴：从确定性物理到会想象的模型

### 3.1 我们已经有一个世界模型

本书卷四讲了 FlowSim：运动学/动力学积分 + OBB 碰撞 + 重力贴地。它是一个**确定性的、
解析的、可复现的**世界模型——每帧回答「如果我给这个油门，世界下一帧会怎样」。这个
价值常常被低估：**大多数做驾驶的团队没有这样干净的可微物理环境**，而它正是世界模型
研究的理想"真值老师"。

### 3.2 生成式世界模型：学出来的预测器

学术界的生成式世界模型（Dreamer 系列、基于模型的强化学习 MBRL）用神经网络预测
「状态 + 动作 → 下一状态」的分布，并在想象中 roll out 来训练策略。它的卖点是不需要
真实环境的无限采样，但代价是**预测会漂移**（误差随步数累积）。

**与本项目的关系**：`ai_framework.py` 已定义 `WorldModelState / Action / Prediction`
（含不确定性）契约，`KinematicWorldModel` 是确定性参考。两步演进：

1. **让 FlowSim 当老师**：在仿真里做海量 roll out，让生成式模型学习「预测误差」，
   而不是从零学世界——这比从真实车采样便宜几个数量级；
2. **概率占用进 ST 图**：世界模型给「前方 20m 可能有人」的分布，DP 的代价从 0/1 墙
   变概率加权（和 2.3 的占据网络是同一枚硬币的两面）。

**一句诚实的冷水**：生成式世界模型至今没有在真车上证明「比确定性物理更好用」——
它的价值更多在**训练期的想象**，而不是**运行期的预测**。运行期，确定性模型依然
更快更稳。所以更现实的路线是「确定性跑运行、生成式做训练」，而不是「用生成式取代
确定性」。

## 4. 数据轴：不是"采更多"，而是"采对的"

### 4.1 行为克隆的分布漂移问题

BC 有个著名缺陷（DAgger 论文的核心论点）：训练分布和测试分布不一致——老师只在它
见过的场景上示范过，学生一旦偏离，就进入老师没示范过的地带，越开越歪。卷七记录的
DAgger 自我对弈就是治这个的。

### 4.2 数据引擎：把数据当产品做

业界「数据引擎」（Tesla 的 Data Engine、Waymo 的 Data Platform）的核心不是堆采集，
而是**闭环**：路测 → 自动挖掘难例 → 用难例重训 → 再测 → 看难例占比是否下降。
关键组件：

- **难例挖掘**：评估器里 FAIL 的场景（碰撞、偏航、停滞）就是现成的难例——项目
  `scenario_regression` 失败归档 `/tmp/flow_bad_cases/` 已经是难例库的雏形；
- **主动学习**：让模型自己说「这个样本我不确定」，优先标注/仿真它；
- **数据选择**：不是所有数据都有价值，重复数据反而让模型遗忘（灾难性遗忘）。

**与本项目的关系**：`demo_evaluator` 的 FAIL 场景 → `scenarioctl replay` 重放 →
`scenarioctl generate` 生成变体（`--count 20 --seed ... --speed-scale 0.9 --position-jitter`）
——这条链已经是一个**最小可用的数据引擎**：失败场景自动生成变体、扩大难例分布。
缺的只是「自动把难例送进训练集」这一个环节。

### 4.3 仿真是最好的数据工厂

仿真的终极价值不是验证，而是**无中生有地造数据**。`scenarioctl generate` 的变体
生成（速度缩放、位置抖动、随机种子）就是「程序化造场景」。未来的方向是**可控仿真**：
自动生成「恰好卡在系统弱点上」的场景——这需要知道弱点在哪，而弱点就在评估器 FAIL
的档案里。

## 5. 部署轴：从仿真到真车，再到安全落地

### 5.1 sim2real：仿真和真车之间的鸿沟

卷八反复强调「仿真参数到真车要重标」。这是 sim2real 问题：仿真里的传感器、物理、
交通流都太干净。业界的两条解法：

- **域随机化**：在仿真里随机化传感器噪声、物理参数、光照——让模型学会「对域不敏感」，
  而不是对某个特定仿真域过拟合；
- **神经重建仿真**：用 3DGS/NeRF 重建真实场景做渲染（见 5.3），让仿真和真实街道
  「长一个样」。

**与本项目的关系**：`sensor_model` 的噪声注入（高斯/FOV/遮挡）已经是最小号的域随机化。
要往前一步，就是让噪声参数可配置成一组「域分布」，而不是固定值。

### 5.2 影子模式与安全落地

卷七的「影子模式 + promote 门禁」不是我们独创的——它是业界部署自动驾驶模型的
**标准安全模式**（Tesla 影子模式、Waymo 的 staged rollout 都是）。这条路线已经被
证明是「从仿真到真车」最稳妥的桥。未来可加强的：

- **离线回放评估**：新模型在**历史真实数据**上回放（而不是只在仿真里），看它跟
  真车实际行为差多少——`ai_framework.py --evaluation` 已支持对 evaluator 结果做
  shadow rollout；
- **运行时安全监控**：不只相信模型，还要有一个独立的「监控网络」判断模型是否已
  脱离训练分布（OOD 检测）——超出分布就降级到规则控制。这正好是 safety_control
  该干的活。

### 5.3 3DGS 与神经渲染：让仿真"长得像"真实街道

3D 高斯泼溅（3D Gaussian Splatting）用可微高斯体表达场景，几十万高斯即可实时渲染
一个真实重建的街区。它和项目的关系有两个层次：

**第一层（可视化）**：用实车采集的相机/雷达重建真实路段 3DGS，替代手工搭的
glTF 模型——FlowBoard 的 3D 场景从「手工建模」变成「真实重建」，画面真实度上一个
台阶。**注意分层**：3DGS 只负责「像不像」（观感），碰撞/路沿/车道线的判定仍走
确定性几何（卷六的「功能几何 vs 纯观感」分界线不变）。

**第二层（仿真数据）**：神经重建仿真（NEURAL SIM 一脉）把 3DGS 重建的街区当成
**渲染后端**，配合程序化布置的交通参与者——这就是「长得像真实街道、内容可编程」
的仿真器，是 sim2real 的一条强路。这也是数据轴（4.3）的升级：仿真造的数据不再是
「卡通街景」，而是「真实街景 + 人造车流」。

### 5.4 车端推理优化：模型落地前的最后一关

前沿模型（VLA、占据网络）普遍太大、太慢，跑不进车端实时控制链。业界标配三板斧：

- **量化**：FP32 → INT8/INT4，快 2-4 倍，代价是精度损失要评估；
- **蒸馏**：大模型教小模型，把能力压进能在车端跑的规模（tiny-MLP 思路的放大版）；
- **NPU/专用加速**：GPU 之外，NPU（如地平线、Mobileye）对定点推理更友好。

**与本项目的关系**：`tiny_mlp.h` 的纯 C 单隐层内核就是「蒸馏到极致」的示范——模型
小到可以在车端零依赖推理。前沿模型落地项目的路径，大概率是「大模型离线蒸馏 →
tiny 规模车端推理」而不是「把大模型塞进车」。

## 6. 一张未来地图（总结）

| 前沿方向 | 解决什么 | 项目已有骨架 | 最小接入点 | 风险/代价 |
|---------|---------|-------------|-----------|-----------|
| 端到端 / VLA | 消除模块间信息丢失 | `ai_framework.py` VLAAdapter | 影子模式先旁路 | 可解释性消失，需门禁兜底 |
| 大模型决策 | 常识/语义级路线意图 | 行为层 8 状态 FSM | LLM 输出离散状态 | 时延/成本，不适合连续控制 |
| 离线 RL / DT | 摆脱专家上限 | 评估器评分 = 回报信号 | temporal_train 扩成 DT | 回报标定难 |
| BEV / 占据网络 | 感知漏检即灾难 | ST 图时空网格 | 占用概率进 DP 代价 | 感知升级工程量大 |
| 生成式世界模型 | 训练期无限想象 | FlowSim = 确定性真值老师 | 学预测误差 | 运行期仍不如确定性模型 |
| 数据引擎 | 采"对的"数据 | 评估器 FAIL → 变体生成 | 难例自动进训练集 | 数据管线工程 |
| 3DGS 神经渲染 | 仿真像真实街道 | flowboard 3D / glTF | 重建真实路段做可视化 | 只解决观感，不解决判定 |
| sim2real 域随机化 | 仿真参数难迁移 | sensor_model 噪声注入 | 噪声参数化成分布 | 需大量真车校验 |
| 车端推理优化 | 大模型跑不进车 | tiny_mlp 零依赖内核 | 大模型离线蒸馏 | 蒸馏质量损失 |

## 7. 判断框架：未来技术要过"五关"

不管哪根轴的技术，要进入这个项目，都必须通过五关——它们正是全书九卷的原则，不是
展望：

1. **职责铁律不破**：模型是乘客，不是驾驶员。planning 仍是轨迹权威，safety 仍是
   最后闸门。模型可以出「意图」，不可以绕开安全链出「执行量」。
2. **影子模式先行**：任何新模型先旁路对比（`inference/trajectory`），promote 门禁
   评估通过才晋级。学歪的模型在影响驾驶之前被拦下。
3. **Python 仿真先行**：模型行为先 `--run-all` / `--evaluation` 验证，再动 C++。
4. **门禁有效**：新能力必须能被评估器抓住故障，否则它的 PASS 不可信（卷九）。
5. **单一数据源**：新模型的输出落进 `/tmp/flow_topology.json`——可观测，才可验证。

**一句话**：这本书写的是「车架」——铁律、验证、影子模式、单一数据源。未来的技术
无论多前沿，都只是乘客；车架不变，谁来坐都安全。这也是做自动驾驶最该有的心态：
**对模型保持开放，对安全保持偏执。**
