# 第 21 章：VLA、世界模型与无人车的前沿

> **本章导读**：
> 前 20 章讲的都是**模块化**架构：感知出一个个目标框，规划出一条几何轨迹，控制解出方向盘角度，每层都有明确的输入输出和可以单测的接口。而 2024 年之后整个行业在往另一个方向走——**端到端**（端到端驾驶），以及更进一步把视觉、语言、动作统一进一个模型的 **VLA**（Vision-Language-Action）。
>
> 这一章是全书唯一一章**大量引用仓库外材料**的章。写它的目的不是让读者改代码，而是提供一副坐标系：
>
> - 读完前面 20 章，你知道了模块化怎么做、代价是什么；
> - 这一章告诉你另一条路长什么样、走到哪了、以及**它和你刚读的那些章节是什么关系**；
> - 第 22~24 章会讲 FlowBoard 3D 可视化、评估器和端到端学习闭环——那三章正好是本前沿趋势在本仓库的落点。
>
> **关于可信度的说明**：本章的数字全部标注了来源。凡是公司营销口径而非可复现测量的，我明确写出来；凡是我无法独立核实的，我标为「未能核实」。请按这个分级来读——尤其是自动驾驶行业，PR 数字和测量数字的差距经常是数量级的。

## 1. 为什么要写这一章

2020 到 2024 年，自动驾驶的主流架构是模块化流水线。你在第 13~20 章读到的正是这个范式：模块之间用结构化消息通信，每一层都可以独立验证，出问题能定位到具体模块。

这套架构的问题也很清楚，而且从 2025 年起被反复讨论：

| 模块化的问题 | 表现 |
|---|---|
| **误差级联** | 感知的 5 cm 误差 → 预测的轨迹偏移 → 规划的绕行决策改变 |
| **长尾组合爆炸** | 模块各自覆盖不了「雨天 + 逆光 + 加塞 + 施工区」这种组合 |
| **难以穷举测试** | 每个模块可以单测，但模块间的交互组合没法穷举 |
| **维护成本随规模上升** | Waymo 的说法是「模块化意大利面在规模化时变得不可维护」 |
| **决策不够「类人」** | 路口博弈、礼让判断这类语义推理，规则难以编码 |

端到端（E2E）的思路是：**直接从摄像头像素映射到轨迹或控制量**，中间不设显式中间表示**。**

但纯 E2E 有一个致命的验证问题（Waymo 的原话）：

> **"You can't build trust with a black box."** 纯端到端神经网络存在黑箱失效的风险……我们已经加了一个独立的机载验证层。这个架构选择对于安全地扩展到 L4 是不可谈判的。

这句话是理解 2026 年整个行业走向的钥匙。**共识不是「E2E 赢了」，而是「E2E 用于策略，结构化表示 + 独立验证用于安全和可调试性」。**

## 2. VLA：把视觉、语言、动作塞进一个模型

### 2.1 三种动作接口

2026 年最重要的技术共识不是某个模型胜出，而是**收敛到了三种动作头设计**，且它们有可测量的性质差异。这个分类最清晰地表述在理想汽车 MindVLA-U1 论文（arXiv:2605.12624，2026-05-12）里：

| 设计 | 做法 | 论文指出的弱点 |
|---|---|---|
| **离散 token 自回归** | 轨迹作为数字 token 从语言头输出（全自回归，或 block-diffusion） | 「tokenizer 精度下限」；继承语言模型的幻觉 |
| **离散 token + 下游解码器** | VLM 输出离散轨迹 token，独立解码器还原连续动作（如 NVIDIA Alpamayo-R1） | 动作生成在主干前向之外 |
| **VLM + 独立动作专家** | 动作走 cross-attention 专家，有自己的 attention/FFN（如 π₀ 系列） | 「VLM 特征是在没有动作上下文的情况下构建的」——VLM 从来看不到动作 token |

MindVLA-U1 自己的贡献是第四种：**统一共享主干**——带噪的动作 token 像视觉和语言 token 一样流过每一层 transformer，用一个薄的 flow-matching MLP 在动作位置读出速度，另加一个语言头。一次前向、两个损失、梯度共享。

### 2.2 一个反直觉的发现：喂更多帧反而更差

这是 MindVLA-U1 里最值得记住的消融结果：

| 配置 | RFS 分数 |
|---|---|
| 单帧进 VLM | **7.69** |
| 4 帧进 VLM（DeepStack，约 2.2× token） | **7.61**（更差） |
| 加学习式流式记忆通道 | **7.89**（+0.10） |

**多帧视觉 token 是高度冗余的，通用 VLM 没有被架构训练成把它们压缩进规划相关的时序状态。** 显式的记忆通道才是对的抽象。

这对你理解第 23 章的流式记忆设计有直接价值。

### 2.3 延迟：这是语言问题，不是算力问题

MindVLA-U1 报告的延迟分解（1×H200，Qwen3-VL-2B 稠密，bs=1）：

| 路径 | 延迟 | FPS |
|---|---|---|
| 完整 VQA 优先（22 步扩散） | 2,594 ms | 0.39 |
| 仅动作（22 步） | 103 ms | 9.70 |
| VQA 快路径（22 步） | 108 ms | 9.26 |
| **VQA 快路径（11 步）** | **63 ms** | **15.92** |

阶段拆解（22B 稠密配置）：prefix embed ~30 ms、VQA prefill ~40 ms、**VQA 自回归解码 ~2,450 ms（30.4 ms/token，占慢路径 94%）**、动作扩散 38 ms（11 Euler）/ 74 ms（22 Euler）。

> [!IMPORTANT]
> **94% 的慢路径延迟来自语言的自回归解码。**
>
> 应对办法不是把模型做小，而是**把语言 token 物理地从序列里移除**——用 attention mask 组合实现快/慢双路径，而不是运行时启发式路由。这是「VLA 太慢做不了控制」这个问题的架构答案。

**而快路径的代价是精度下降**：7.82（22 步）→ 7.67（11 步）。快慢路径之间没有免费的午餐。

### 2.4 车载延迟：公开数据非常稀缺

| 系统 | 延迟 | 硬件 | 备注 |
|---|---|---|---|
| NVIDIA Alpamayo-R1 | **99 ms** | 论文未点名 SoC | 真实车载路测，8 万小时 / 1700+ 城市 / 25 国数据训练 |
| MindVLA-U1 快路径 | 63–108 ms | **1×H200**（数据中心级） | 仿真测量，非车载 |
| Tesla FSD v14.3 | 未公布 ms | AI4/AI5 | 只说「用 MLIR 重写编译器，反应时间快 20%」 |

> **注意 Alpamayo-R1 的 99 ms 是在「车载路测」上测的，但论文正文没有点名 SoC；而 MindVLA-U1 的 63 ms 是在 H100/H200 上测的。** 这两个数字**不可直接比较**。
>
> 我没有找到任何 2026 年的 VLA 论文报告在 DRIVE Thor 或 Orin 上的延迟。这是公开记录里的一个真实空白。

### 2.5 VLA 真的赢了吗？一个诚实的对照

同一批数据、同一主干下 VLA vs 纯视觉-动作（VA）的对照（MindVLA-U1 验证集，WOD-E2E 基准）：

| 模型 | RFS |
|---|---|
| VAD | 4.45 |
| UniAD | 5.78 |
| RAP-DINO（**纯 VA**，DINOv3-H） | 7.91 |
| MindVLA-U1 + Intent-CFG（**VLA**） | 7.92 |
| Poutine（纯 VA，2025 Waymo 挑战赛冠军） | 8.12 |

**VLA 只在接口修好之后才勉强超过纯 VA，差距是 0.1~0.2 RFS，不是数量级的差异。**

MindVLA-U1 自己的摘要坦承：驾驶 VLA「常常在规划质量上落后于 VA」，并把这归因于**接口失败**而非范式极限。

而 Poutine（纯 VA）在测试集拿到 7.99，是 2025 年 Waymo 挑战赛第一名，它的论文说「不需要在基础 VLM 上加手工 tokenizer 或自定义架构组件」。

> **这是一个尚未解决的学术张力，不是有定论的结果。**

### 2.6 一个更惊人的发现：语言能力和驾驶质量是解耦的

MindVLA-U1 报告：把基础版 Qwen3.5-VL-2B 换成指令微调版，语言指标（BLEU-4 / ROUGE-L）从 0.27/0.48 **崩到 0.12/0.29**，而驾驶规划分 RFS 几乎不变（7.94 → 7.91）。

**这意味着：驾驶 VLA 的可控性走的是场景表示，不是语言流利度。**

这个结果的含义很大——它暗示「VLA 里的 LLM 可能不是必需的」。目前没人证明这一点，但这是 2026 年最值得跟踪的开放问题。

### 2.7 Scale law：预测规划有，端到端 VLA 没有

- **Waymo 找到了干净的幂律 scaling**（50 万小时数据，arXiv:2506.08228），任务是运动预测和规划；
- **MindVLA-U1 发现非单调**：0.8B / 2B / 4B / 9B 对应 7.81 / 7.94 / 7.86 / 7.84。

作者明确拒绝把这读作范式结论，并列出四个混淆因素（训练调度、数据、动作头容量、评测通道）。他们的训练集只有约 2000 条序列——**这个规模不足以显现 scaling law**。

诚实的总结：**scaling law 已在预测和规划任务上确立，尚未在「带语言的端到端驾驶」上证明。**

## 3. 世界模型：给端到端策略一个能闭环的世界

### 3.1 两种世界模型

NVIDIA Cosmos 3 技术报告（arXiv:2606.02800，2026-06-22）给出了最清晰的分类，这段原文值得引用：

> 一个有用的区分是**预测式潜空间世界模型**（学习紧凑的内部动力学用于规划与控制）与**生成式世界模型**（把预测的未来作为可检视的多模态仿真暴露出来）。预测式潜空间世界模型学习紧凑的隐状态，其价值在于让规划与控制更廉价……生成式世界模型把仿真本身作为建模接口：模型把可能的未来观测预测为图像、视频、音频……这让几何、接触、时序和声音中的错误**可被观察，而不仅仅是从任务损失中推断**。
>
> 对一个智能体来说，视频只有在变化能追溯到状态、动作和接触时才有用；**否则真实感并不意味着可靠的仿真器。**

**2026 年所有量产自动驾驶的世界模型都在「生成式」这一侧。** 潜空间那一侧主要存活在学术 RL 工作里（Dreamer、JEPA、Think2Drive）。

### 3.2 Waymo World Model

Waymo 博客，2026-02-06，可能是这一年最重要的发布：

- 基于 **Google DeepMind Genie 3**（实时交互世界模型，24 fps，720p，可维持数分钟一致性）后训练而来
- **同时生成相机和激光雷达（4D 点云）输出**——把 Genie 3 的 2D 世界知识迁移到 Waymo 的 3D 激光雷达
- 三种控制机制：**驾驶动作控制**（反事实：「如果当时选择抢行而不是让行会怎样」）、**场景布局控制**（路网布局、信号灯状态、他车位置）、**语言控制**（时段、天气、全合成场景）
- 可以把**任意行车记录仪/手机视频**转成多模态仿真
- 展示了龙卷风、洪水、大象、长角牛、狮子、滚动灌木、穿霸王龙服装的行人
- 长时序 rollout 达 **4× 实时回放**
- **明确对比了 3DGS 等重建方法，并站在生成式一边**：「纯重建方法（3D Gaussian Splats）会因观测缺失而在模拟路线与原始行驶差异过大时产生视觉崩坏，而完全学习式的 Waymo World Model 依靠强生成能力保持了良好的真实感与一致性」

> Waymo 没有披露该模型的参数量、算力或后训练数据量。

### 3.3 XPeng X-World：最详实的工程报告

arXiv:2603.19979（2026-03-31）：

- WAN 2.2 5B 基座；3D 因果 VAE（16×16 空间、4×4 时间压缩，48 潜通道）
- 定制 DiT + **view-temporal self-attention**；按条件类型解耦的 cross-attention 分支
- 条件：自车动作（速度、曲率、侧倾、俯仰）、动态体（umT5 类别 + Fourier 坐标）、静态元素、相机内外参、文本
- **两阶段训练**：Stage I 双向 I2V → Stage II **chunk-wise 因果 + 少步 self-forcing**（DMD 蒸馏，4 步去噪/chunk，滚动 FIFO KV cache）→ 流式自回归仿真器
- 展示了 **24 秒多相机 rollout**

**部署数字**（公司博客，2026-04-29）——公开记录里最具体的生产世界模型数据：

- XPeng 仿真场景一年内从 **30,000 → >500,000**
- **等效每天仿真测试里程 3000 万公里真实驾驶**
- 用于：VLA 2.0 的闭环评估（碰撞率、目标完成进度、乘坐舒适性）、**在线 RL**、数据合成（罕见场景、「隐藏行人」的鬼探头、海外风格迁移如左舵交通）

> XPeng 在 CVPR 2026 另外声称「单任务训练效率提升 4360%」——**公司口径，未给基线**。

### 3.4 世界模型到底怎么帮到策略？四个具体机制

大多数写这块的文章都很含糊。实际有据可查的只有四条：

1. **反事实评估 / 闭环回归测试。** XPeng：日志里自车在一辆**停放**的车后面等着；X-World 展开另一种可能（绕行），让策略被打分，看它是否会采取更高效同时安全的动作。Waymo：「Waymo Driver 当时是否本可以更大胆地开过去而不是让行」。
2. **在学习到的环境里做在线 RL。** XPeng 用 X-World 当 VLA 2.0 的 RL 环境，压制路口「隐藏行人」鬼探头和犹豫变道，并学习从近似事故状态恢复。**这是唯一一条有可能真正解决「日志是闭环绑定在人类行为上，学不了新东西」这个根本问题的机制。**
   > X-World 论文里有一句难得的诚实：C2V 模式（L=0）「严格来说不是世界模型，因为它不条件于当前观测状态，因此不建模状态转移」。
3. **长尾数据生成。** XPeng 程序化生成极端天气、罕见车型、异常行人；零样本风格迁移把中国数据变成欧洲/左舵资产。Waymo 把行车记录仪转成仿真。
4. **闭环规模扩展。** Waymo 的表述最锋利：「仅仅重放记录数据，也就是开环仿真，是不够的，因为那就像走进一个视频回放——周围交通在动，但对你的动作完全无动于衷。」

**第五条，商业上很有趣：小马智行 PonyWorld 2.0**（2026-04-10）——模型形成「意图层」内部表示，自比意图与实际结果，识别具体失败场景，**然后指导人类工程师去采集恰好所需的真实数据**。CTO 声称「让 Robotaxi 车队能同时部署到多个国家和城市，而工程资源不成比例增加」——**这是管理层断言，不是测量结果**。

### 3.5 生成式世界模型 vs 传统仿真（CARLA / esmini / SUMO）

> **没有找到严谨的同行评审 head-to-head 对比。** 以下是两边的论证：

- **支持生成式**（Waymo）：3DGS/重建「因观测缺失，在模拟路线与原始行驶差异过大时产生视觉崩坏」。
- **支持重建**（NVIDIA AlpaSim、Wayve Ghost Gym、Applied Intuition Neural Sim、多数学术界）：重建给出**传感器精确、物理有据**的闭环，其他交通参与者有真实轨迹。Applied Intuition 明确把闭环下游指标称为「金标准」。

**务实结论**：行业已经收敛到**分层仿真**——生成式模型叠加在或并列于重建之上，而不是取代它。而且有个值得注意的事实：**NAVSIM v2 的 Stage-2 评估用的是预生成的 3DGS 合成后续观测**——也就是说，当前最重要的端到端规划基准**已经依赖 3DGS 重建**。（这一条来自二手汇总，**建议对照 NAVSIM 仓库核实**。）

### 3.6 谁在做真实行驶的神经重建

| 玩家 | 做法 | 时间 |
|---|---|---|
| Waymo World Model | 生成式，相机 + 激光雷达，动作/布局/语言控制，4× 实时，dashcam→仿真 | 2026-02 |
| Applied Intuition Neural Sim | 辐射场/Gaussian Splatting，重建动态体并使其动画化，相机+激光雷达+毫米波；**每天运行数千次神经仿真**验证自家 SDS | 2025-10 |
| NVIDIA AlpaSim | 从真实日志做时序 3DGS，自车偏离时做新视角合成 + MPC 跟踪，开源 | Alpamayo-R1 引用 |

## 4. 行业落地：2026 年在跑什么

### 4.1 Waymo

- **纯无人驾驶里程（截至 2026 年 6 月）：2.713 亿英里**（Waymo Safety Impact 数据中心，一手来源）。分城市：Phoenix 9212 万、湾区 8242 万、洛杉矶 6710 万、Austin 2106 万、Atlanta 862 万。

- **每周 50 万次付费载客，覆盖 10 个美国城市**——2026-03 由联合 CEO Dolgov 公布（来自 X/播客，TechCrunch 2026-03-27）。相比 2024-05 的约 5 万/周是十倍。
- 目标：**2026 年底前每周超 100 万次付费载客**（2026-02 Waymo 博客引用联合 CEO Tekedra Mawakana）。
- 2026-09-01 新增 Denver、San Diego、Tampa → **14 个美国城市**（二手来源；Waymo 官方城市列表是权威）。

### 5.1 UNECE ADS 全球技术法规：2026-06-24 通过

**这是本年度的头条监管事件。**

WP.29 第 199 次会议（日内瓦，2026-06-22~26）通过了**全球首个全无人驾驶 ADS（SAE L4/L5）的监管框架**，同时通过 1958 年协定下的**联合国法规**和 1998 年协定下的 **GTR**。

## 6. 安全论证：一场测量纪律之争

### 6.1 Waymo 的数据（一手：Safety Impact 数据中心，截至 2026-06，2.713 亿纯无人英里）

| 结果 | Waymo IPMM | 基准 IPMM | 降幅 |
|---|---|---|---|
| 严重伤害或更严重 | **0.01** | 0.21 | **−94.82%** |
| 任何伤害（报告口径） | **0.67** | 3.77 | **−82.13%** |
| 任何车辆安全气囊弹出 | **0.29** | 1.62 | **−81.75%** |
| Waymo 自身车辆安全气囊弹出 | **0.05** | 1.06 | **−95.48%** |

弱势道路使用者：行人 −93%、骑行者 −86%、摩托车 −82%。

**41% 的 SGO 报告碰撞 ΔV < 1 mph**（SF 43%、PHX 39%、LA 40%、ATL 42%、ATX 34%）。

按碰撞类型的任何伤害降幅：路口车车碰撞 **−96%**、单车 **−97%**、行人 −93%、骑行者 −86%、摩托车 −82%、**车车追尾 −48%**（**降幅最小的一类**）。

### 6.2 方法论（多数书会写错的部分）

- 基准来自 **Scanlon et al. 2024**（arXiv:2312.13228, *Traffic Injury Prevention*）和 **Kusano et al. 2025**，同行评审
- 人类基准**限定在 Waymo 运营所在县**、**排除高速**，并按 Chen et al. 2024 做**动态空间重加权**以匹配 Waymo 实际驾驶分布
- **车辆级**（非事故级）——Waymo 详细解释了为什么事故级基准会高估 AV 事故率（示例：0.5 起事故/100 英里 vs 1.0 辆事故车/100 英里，会得出「2 倍更差」的错误结论）
- 任何伤害基准用 **32% 漏报修正**（Blincoe et al. 2023, NHTSA 技术报告 813403）；安全气囊和严重伤害**不做修正**
- IPMM 用 Poisson 精确置信区间；降幅用 Clopper-Pearson；95% 水平
- 符合 **RAVE 检查表**
- **所有原始数据以 CSV 形式公开**，结果可独立复现

### 6.3 Safety Case 层

Waymo Safety Framework（arXiv:2011.00054）和 **Safety Case 方法论**（发表于 *Traffic Injury Prevention*，2025，「一套任何公司都能用的详尽蓝图」）。

Waymo 明确区分两者：「关于『足够安全』的主张通过 Safety Framework 和 Safety Case 在发布某个 ADS 配置**之前**做出；Safety Impact 数据中心提供的回顾性证据起**部署后验证**作用。」

NHTSA 2025-11 的研讨会把「safety case 组件」列为圆桌议题——**Safety Case 正在成为监管通用语**。

### 6.4 持续存在的批评（必须诚实列出）

1. **没有「仅死亡」这一档。** Waymo 自陈：「目前 Waymo 里程不足以在运营区域达到统计显著性，因此我们不单列仅死亡这一类。」严重伤害数据很好，最罕见的结果是未测量的。
2. **基准是「平均人类驾驶员」，不是匹配样本。** Waymo 的论证（IMO）是正确的——「与现状对比」才是安全影响问题——但**没有出租车或网约车司机的公开数据**，也没有「无醉酒、睁眼应对冲突」的基准。
3. **对安全气囊和严重伤害不做漏报修正。** 这是保守选择，但意味着降幅可能被低估——或者比较在反方向上不可比。
4. **统计功效论证是一个修辞动作。** Waymo 的 FAQ 论证数千万至上亿英里足以对数十亿/数万亿产生显著性，用了一个固定 34 起事故、7110 万英里的示例。批评者指出结论完全取决于假定的基准里程；答案是「如果基准超过 1 亿英里，几乎看不出差别」——**这是关于基准不敏感性的陈述，不是关于 Waymo 的**。
5. **ODD 窄，且是刻意的。** 运营城市无降雪。Waymo 承认了。
6. **远程协助和人类远程操作员。** Waymo 认为 RA 与自主一致（2025-11 独立第三方审计）。批评者认为边界是程度问题。**与 Tesla 那两起涉及远程操作员的事故对照，是这个问题最锋利的例证。**
7. **不做责任归属。** 所有事故无论责任都计入，这对率是保守的，但意味着无法做「避免事故」的归因。
8. **RFS/开环基准问题同样适用于安全论证**：整个 VLA 的公开证据基础都是开环的，而开环指标「常规地无法预测路上行为」（MindVLA-U1 自己的话）。

> **我没能找到一篇直接批评 Waymo 安全影响方法的同行评审论文。** 流传的批评来自倡导组织（如 Center for Auto Safety）、评论文章和回顾性分析研究者。**如果本章需要一篇正式引用的反驳论文，它可能还不存在。**

## 7. 工程现实

### 7.1 端到端 vs 模块化：当前的真实共识

**共识不是「端到端赢了」，而是「端到端用于策略，结构化中间表示和独立验证用于安全和可调试性」。** 三家一手来源从三种不同架构说了同一件事：

**Waymo**（2025-12 + 2026-08）：学习到的 embedding 作为接口，**加上**物化的结构化表示（目标、语义属性、roadgraph），**加上**独立机载验证层，**加上** Critic。对模块化时代的评价：「行业依赖专用模块……虽然敏捷，但这种模块化意大利面在规模化时变得不可维护」——并主张更少、更大、更**专用**的基础模型，附带关键限定：「更少模型更好，但那不意味着我们要把处理整合成一个黑箱。」

**NVIDIA**（Alpamayo-R1）：明确是「模块化 VLA 架构」——设计哲学强调灵活性和模块化。这里的模块化指可替换的 VLM 主干 + 可替换的视觉 tokenizer + 可替换的动作专家。

> [!IMPORTANT]
> **X-World 论文给出了模块化为何必要、又为何正在消失的最强结构性论证——而它是关于评估，不是架构：**
>
> 「与模块化流水线不同（那里中间输出可以单测，例如检测 AP、跟踪 MOTA、预测 ADE），端到端策略通常只能通过闭环驾驶结果来评估，而这些结果对细微的分布偏移和误差累积高度敏感。」
>
> **这就是世界模型在 2026 年爆发的真正原因：端到端杀死了单元测试，所以你需要一个仿真器把信号找回来。这是个测试基础设施故事，不是建模故事。**
>
> 这一条对本书前面 20 章是一个深刻的回响：第 18 章讲 FlowSim，第 22 章讲评估器——**它们本来就是端到端的前置条件。**

### 7.3 什么才是真正难的

**长尾。** WOD-E2E 目标是事件频率 < 0.003% 的场景。MindVLA-U1 的 Intent-CFG 演示是最清晰的说明：条件在 `u_turn`、`starting`、`reversing` 上能产生机动的**方向**，但「轨迹保真度受训练数据覆盖限制：罕见意图几乎没有或根本没有 GT 样例」。**可控性是真的，能力不是。**

**评估指标的公开破产。** 加州在替换脱离率（第 5.5 节）；开环 RFS「可能在闭环策略质量之前饱和，没有闭环评估通道时 RFS 上的 scaling 曲线会低估规模的价值」。

**「最后 1%」**。诚实的 2026 年答案：这是**仿真保真度和验证覆盖**问题，不是感知问题。
- Waymo 仍然依赖真实自主里程：「世上没有任何东西能替代这个规模的真实世界全自主经验——再多的仿真、人工驾驶数据采集、或有测试司机的运营都无法复制那种情境的全谱系。」
- **但 NVIDIA Alpamayo-R1 的闭环评估只有 75 个场景，而且排除了每一个自车偏离日志超过 4 m 的案例。** 这个排除条款在做巨大的工作：被评估的模型恰恰是最可能偏离的模型。

**一个更深的坑**（NVIDIA 的 CoC 论文自己说）：自由形式的思维链推理轨迹包含「因果混淆」——标注者看完整段视频，引用了模型观察不到的未来事件。**如果你的监督信号泄漏了未来，你的长尾学习就部分是在记忆一个标签artifact。**

**这个架构本身就是 2026 年行业共识的一个具体实例**：模型（`inference_node`）在线但不直接驱动车辆；`safety_arbiter` 在规则控制之上做仲裁；`safety_control` 是独立的机载验证层。

### 8.2 明显缺的

对照第 7.1 节的共识，本仓库的差距是清楚的：

1. **没有中间表示的物化。** Waymo 的做法是把目标、语义属性、roadgraph 物化，使闭环仿真和验证成为可能。本仓库的消息（`Obstacle` 列表、轨迹点）算是轻量版，但没有针对安全验证设计过。
2. **仿真不能快进。** 第 20 章 1.2 节：墙钟钉死 60 Hz。这是评估吞吐量的硬上限。
3. **NPC 不反应。** 没有动作条件化——这是「世界模型」和「传统仿真」的分水岭。
4. **天气模型 25 行。** 无太阳角度、无天气-μ 耦合。
5. **没有反事实评估。** 场景是固定的，`choreography` 是脚本化的，没有「如果当时抢行会怎样」的展开。
6. **安全阈值全是硬编码。** 第 18 章 9.2 节那 30+ 个字面量，意味着无法做环境自适应的策略。

### 8.3 最有价值的一条借鉴

如果只从本章带走一条工程建议，是这个：

> **端到端杀死了单元测试，所以你需要一个仿真器把信号找回来。**

对本仓库的具体含义：**FlowSim 和评估器（第 20、23 章）不是「有了模型之后才需要的东西」，它们是端到端的前置基础设施。** 一个没有闭环仿真和可靠评估器的团队，一旦把 `inference_node` 从影子模式切到接管，会立刻失去所有回归能力——因为模块化的那些单测（检测 AP、跟踪 MOTA、规划 ADE）全都失效了。

这正好解释了为什么第 18 章那套仲裁（降级 > 包络 > 制动）必须在**任何**端到端切换之前就位。

## 9. 未能核实的事项

诚实起见，列出我没能独立验证的东西：

1. **理想汽车原始 MindVLA 论文。** 2025 年的 MindVLA 架构（MoE、3D ViT 编码器、3DGS 世界模型、GTC 2025 公告）只存在于**中文二手报道和 36Kr/Gasgoo 覆盖**中。找不到 arXiv 论文或技术报告。**只有 MindVLA-U1（arXiv:2605.12624）是一手可引的。**

3. **Bench2Drive 确切分数。** 来自排行榜聚合站而非官方仓库。排序稳健，小数位建议核对。
4. **Waymo 当前城市数和周载客量。** 50 万/周（2026-03）和 14 城（2026-09）来自对其 X 帖的新闻聚合。**2.713 亿英里里程和所有事故率数字是一手的。**

8. **一篇批评 Waymo 安全方法的同行评审论文。** 未找到。
9. **NHTSA/UNECE GTR 最终文本。** 读的是 NHTSA 对 2026-06-24 通过的总结（91 FR 48485）和 UNECE 新闻稿，不是 GTR 本身。
10. **小马 PonyWorld 2.0 的技术实质。** 只有新闻稿和高管引述，无论文、无基准、无消融。

## 10. 思考题

1. **给本仓库设计影子→接管的切换闸门**：
   第 8.3 节说「没有闭环仿真和可靠评估器的团队，一旦把 `inference_node` 从影子模式切到接管，会立刻失去所有回归能力」。假设你要做这个切换，请设计一个切换判据：
   (a) 需要哪些指标？注意加州刚废除了脱离率（第 5.5 节），而本仓库 `demo_evaluator.py` 当前用什么指标？参照第 23 章。
   (b) 按第 7.1 节的三方共识（端到端用于策略，结构化表示 + 独立验证用于安全），本仓库现有的 `safety_arbiter` P1 门闸（`is_degraded` 时屏蔽模型）在切换中扮演什么角色？它够吗？
   (c) 切换之后，第 18 章那 30+ 个硬编码的物理阈值还需要人工标定吗？哪些必须变成随场景自适应的？参考 Tesla 的教训：他们自己承认 HW3 硬件无法支持无监督 FSD——**硬件底座是这个问题的硬约束。**

2. **长尾的可观测性**：
   第 7.3 节指出 Alpamayo-R1 的闭环评估「排除了每一个自车偏离日志超过 4 m 的案例」，而这在做巨大的工作。本仓库的 FlowSim 场景是手写脚本的固定工况。
   (a) 设计一个「偏离即采样」机制：如何从 FlowSim 的运行中自动发现新工况，并把它变成一个新的回归场景？注意第 20 章 8.2 节说仿真**不确定**（srand 一次、总线驱动）——这对自动挖掘意味着什么？
   (b) 参照小马 PonyWorld 2.0 的「意图层 + 导向数据采集」思路（3.4 节第 5 条），给本仓库设计一个轻量版本：模型输出意图，执行器记录实际结果，二者比对后生成一个「需要补采的场景」清单。要比对什么？
   (c) 更根本的问题：**在闭环仿真里发现的新工况，有多少是真实的尾部，有多少是仿真器的 artifact？** 请给出一个区分这两者的判据。参考第 4.5 节——NVIDIA AlpaSim 是 3DGS 重建的，FlowSim 是几何+启发式 NPC，两者的 artifact 性质完全不同。

3. **「加更多帧更差」这个结果，对记忆架构意味着什么**：
   第 2.2 节的多帧消融（7.69 → 7.61）和学习式流式记忆（+0.10）说明：通用 VLM 不擅长把多帧冗余 token 压成规划相关状态。
   (a) 回到本仓库：第 11~13 章的感知/融合链路是**逐帧独立**的（EKF 的 CTRV 传播、Hungarian 关联），本质上是手工设计的时序压缩。VLA 的流式记忆通道是这个手工方案的 learned 版本吗？还是两种不同的东西？
   (b) 如果是 learned 版本，**手工时序滤波的可解释性优势还在吗**？考虑第 14 章 EKF 的协方差矩阵——它是调试时判断「定位现在信多少」的直接依据。一个没有协方差的 learned 状态，你出问题时怎么诊断？
   (c) 追问：MindVLA-U1 的实验是**规划质量**（RFS），不是安全。有没有可能「更多帧对安全更好但对规划更差」——即更多上下文让模型更能识别危险，但也让它更犹豫、更不果断？如果有，这和第 2.6 节「语言能力和驾驶质量解耦」是同一类现象吗？

4. **如果让你用世界模型改造 FlowSim**：
   第 8.2 节列了 FlowSim 缺的五点，第 3.3 题问的是「把 NPC 做成反应式的」。现在把两问合起来：
   (a) 假设不做神经世界模型（太贵、太不确定），只做**行为级的反应式**——让 NPC 知道自车的意图和动作，按规则反应。这在 FlowSim 现有架构下可行吗？需要改哪些地方（参考 `npc_ai.cpp` 的 7 个状态和 `NpcState` 枚举）？
   (b) 对比三条技术路线的投入产出：(i) 手工反应式 NPC；(ii) 接入 esmini 或 CARLA 的成熟交通模型；(iii) 训练一个轻量动作条件化的潜空间世界模型。对一个**要写进书里给读者复现**的开源项目，哪条最合理？论证你的选择。
   (c) 最后一问：**这一章讨论的所有前沿，对一个用 20 年经验的人开的自动驾驶项目，有什么用？** Waymo 自己的数据显示什么会替代什么？中文社区有个说法叫「端到端 + 世界模型是终极方案」——请用本章的数据反驳或支持它。提示：注意 2.5 节的 VLA vs VA 对照、7.1 节的三方共识、8.3 节那条「端到端杀死了单测」。
