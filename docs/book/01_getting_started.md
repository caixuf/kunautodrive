# 卷一 · 第一课：让一辆虚拟的车自己往前开

## 本章问题

你想造一辆自动驾驶的车。你写的第一行代码，应该是什么？

如果你脑子里的第一反应是「深度学习」「传感器融合」「高精地图」——停一下。那些是
第十行以后的事。**第一行代码，是先让一辆车动起来。**

这一章的目标非常朴素：**在你的电脑上，让一辆虚拟的车，自己往前开。**

学完本章，你会理解自动驾驶最核心的那个循环——它不是某一个大模型，而是这个：

```
世界 → 感知（车看见了什么）→ 决策（车决定做什么）
     → 控制（车怎么执行）→ 执行 → 世界（下一帧）
```

你会发现，这个循环小得惊人，也难得惊人。

## 你自己的答案：先写一个能动的车

假设现在让你写「让一辆车往前开」。你会怎么写？大多数人会这样：

```c
// 车的位置
double x = 0.0;
while (1) {
    x += 1.0 * dt;      // 每秒往前走 1 米
    sleep(dt);
}
```

恭喜，车动了。但这不是一辆「车」，这是一个「匀速移动的点」。它不会转弯，不会加速，
不会刹车，更不会知道前面有一堵墙。**它只是被推着走，而不是自己开。**

想想现实中的车：踩下油门，车加速；打方向盘，车转向；松油门，车减速。这些动作之间
不是独立的——**你打的方向盘，只在你往前开的时候才有意义**（原地打方向，车只会原地
转圈）。这就是「运动学」：车怎么动，取决于油门、刹车、方向盘**三个量**以及**车自身
的几何**（轴距）共同决定。

## 插曲：坐标系——如何描述一辆车在哪

在继续之前，我们必须先解决一个更基础的问题：**你怎么描述「一辆车在哪」？**

如果你从来没想过这个问题，别急，这正是最容易卡住新人的地方。我们一点点来。

### 第一步：描述一个点

「车在 100 米外。」——这句话在物理上毫无意义，因为**你没有说是从哪算起的 100 米**。

要描述位置，你需要一把「尺子」：先定一个**原点**（从哪量），再定**方向**（往哪个方向
量），然后说「沿着 x 方向走 100 米，沿着 y 方向走 50 米」。这把「原点 + 方向 + 单位」
的组合，就叫**坐标系**。一辆车在世界里的位置，就是一个坐标对 `(x, y)`——它的意思是
「从世界原点出发，沿 x 走 x 米，沿 y 走 y 米」。

### 第二步：描述朝向

但「位置」只回答了一半。一辆车不光**在哪**，还**朝哪**。一辆朝东开的车和一辆朝北开
的车，即使位置相同，也完全不一样。

描述朝向需要一个新量：**朝向角**，我们叫它 `heading`。约定 x 轴正方向为 0 度，
逆时针为正。于是：

```
heading = 0°    车头朝东（+x 方向）
heading = 90°   车头朝北（+y 方向）
heading = 180°  车头朝西
```

有了 `(x, y, heading)` 三个数，一辆 2D 平面上的车就被**完整描述**了。这三个数合起来
有个名字：**位姿（pose）**。这是全书出现频率最高的词，你现在就认识它了。

### 第三步：世界坐标系 vs 车体坐标系

现在到了 transforms（坐标变换）的核心。请做一个思想实验：

> 你的车头上装了一个雷达，它位于**车头正前方 2 米**。现在车朝北开，位置在世界坐标
> (100, 100)。问：雷达的世界坐标是多少？

你可能会脱口而出 `(100, 102)`。恭喜，你刚刚做了一次坐标变换。但请注意——你是怎么
算出来的？你把「车前 2 米」（这是**车体坐标系**里的描述）翻译成了「世界坐标 y+2」
（这是**世界坐标系**里的描述）。因为车朝北，车的前方恰好等于世界的 y 正方向，所以
这次翻译很简单。

**现在把车转个方向：** 车朝东开（heading = 0°），雷达还是「车头正前方 2 米」。
问：雷达的世界坐标是多少？这次不是 `(100, 102)` 了，而是 `(102, 100)`——因为车头
朝东，车前 2 米 = 世界 x+2。

**同一个「车前 2 米」，因为车的朝向不同，世界坐标就不同。** 这就是为什么要学
transforms：**传感器永远在车体坐标系里测量**（雷达「左前方 2 米」），**而地图和规划
在世界坐标系里思考**（「这条路往东北方向」）。你必须在两者之间来回翻译，翻译错了，
车就会「看见」错误位置的东西。

### 第四步：车体 ↔ 世界的公式（你现在就能看懂）

车在 `(x, y)`，朝向 `heading`。车体坐标系里的一个点 `(bx, by)`（向前为 bx，向左为
by），它在世界坐标系里的位置是：

```
wx = x + bx·cos(heading) − by·sin(heading)
wy = y + bx·sin(heading) + by·cos(heading)
```

别被公式吓到——它就是「先旋转，再平移」：先按车的朝向把车体坐标转正，再平移到车的
世界位置。你在第三步做的两次心算，就是这个公式在 `by=0` 时的特例：

- 车朝北（heading=90°）：`cos=0, sin=1` → `wx = x − by, wy = y + bx`。车前 2 米
  （bx=2, by=0）→ `(100, 102)`。对上了。
- 车朝东（heading=0°）：`cos=1, sin=0` → `wx = x + bx, wy = y + by`。车前 2 米 →
  `(102, 100)`。对上了。

**这个公式值得抄在纸上。** 卷三的感知、卷五的地图、卷六的 3D 渲染，全都绕不开它。
项目甚至在卷六专门为「坐标怎么转」立了一条铁律和一套测试——因为坐标转错的 bug 极难
用眼睛看出来（车明明在路中间，但感知以为它在路外）。

### 一个简化的约定

真实世界是三维的（还有高度 z），自动驾驶常用 ENU（东-北-上）作为世界坐标系。但我们
从二维开始——**先把 2D 吃透，3D 只是多一个 z 轴**。现在，回到让车动起来。

## 一个关键问题：车往哪个方向开？

如果你要让车转弯，你的第一个直觉可能是：`x += v*dt; y += v*dt`（x 和 y 同时变）。
但这是错的——车不会斜着开。车只会沿着**它车头所指的方向**开。所以你得先记住
「车头朝向」这个量，我们叫它 `heading`（航向角）。

于是车辆模型变成：

```
前进方向 = (cos(heading), sin(heading))     ← 车头朝哪
x += v · cos(heading) · dt                  ← 沿着车头方向走
y += v · sin(heading) · dt
heading += 某个由方向盘决定的东西           ← 转向
```

这已经是「运动学自行车模型」的雏形了。但还差最后一块：**方向盘和航向角的关系**。

## 真正的方案：运动学自行车模型

下面这段代码是仓库里真实运行的车辆模型（`modules/adas_nodes/flowsim/physics.cpp` 的
`step_bicycle`）。我们不跳着看，逐行讲。

```cpp
void step_bicycle(Entity& e, double dt, double throttle, double brake, double steer) {
    // ① 纵向：油门加速、刹车减速
    e.speed += longitudinal_accel(e, throttle, brake, e.speed) * dt;

    // ② 倒车的正确姿势：只有显式负油门才允许倒车
    //    普通刹车把速度压到 0 就停，绝不能误变成倒车
    if (e.speed < 0.0 && throttle >= 0.0) e.speed = 0.0;

    // ③ 速度有上下限
    if (e.speed < -4.0) e.speed = -4.0;
    if (e.speed >  60.0) e.speed = 60.0;

    // ④ 转向执行器不是瞬时的：它有惯性（一阶滞后）
    update_steer(e, steer, dt);

    // ⑤ 核心：航向角变化率（横摆角速度）
    //    车速越快，同样的方向盘转角转得越猛；轴距越长，越「钝」
    e.yaw_rate = (e.speed / e.wheelbase) * std::tan(e.steer);
    e.heading += e.yaw_rate * dt;
    normalize_heading(e);
    // ...
}
```

**第 ⑤ 行是这个模型的心脏**：`yaw_rate = speed / wheelbase · tan(steer)`。

停下来想一分钟，为什么是「速度除以轴距再乘 tan(方向盘)」：

- 方向盘转角越大，`tan(steer)` 越大 → 转得越急。合理。
- 轴距（前后轮距离）越长，转弯半径越大 → 转得越钝。合理。
- **速度越快，同样的方向盘转角下横摆角速度越大**——这就是为什么高速上打方向盘要
  轻、低速下可以猛打。这是 `speed / wheelbase` 那一项告诉你的。

如果你这辈子只从这本书记住一个公式，记住这个就够了：**它是「车是怎么转弯的」的全部
秘密**，而卷三讲的控制、卷八讲的真车标定，全都要回到这个公式。

### 一个你注意不到的坑：参考点

注意上面代码里的注释——它特别强调用「**车辆中心**」而不是「后轴」作为参考点：

```cpp
// 车辆中心 = 后轴 + half_wb·forward，其速度需叠加绕后轴转动的切向分量
double half_wb = e.wheelbase * 0.5;
double vx_rear = e.speed * std::cos(e.heading);
double vy_rear = e.speed * std::sin(e.heading);
e.x += vx_rear * dt - half_wb * std::sin(e.heading) * e.yaw_rate * dt;
e.y += vy_rear * dt + half_wb * std::cos(e.heading) * e.yaw_rate * dt;
```

如果你用「后轴速度」直接更新「车辆中心」的位置，会发生什么？想象一辆车正在转弯：
它的后轴在绕弯心转，如果你把后轴的速度直接安在车中心头上，车体就会「平移」——视觉
上看起来就是**车尾横着甩**。这就是为什么代码里要叠加一个切向分量：`-half_wb·sin·yaw_rate`
这一项，把「中心随后轴转动」的切向速度补回来。

这个坑，项目真实踩过——它直接导致过一个「掉头时车屁股横移」的观感 bug。你会在卷六
（可视化）再次见到它。**记住：最简单的模型里，也藏着需要深思的细节。**

## 动手实践：跑起来，看看这辆车

现在，让这辆车在你的电脑上真的跑起来。打开终端：

```bash
# 构建（第一次约 1-2 分钟）
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)

# 一键启动演示（构建 + 启动全链路 + 打开浏览器）
bash scripts/demo.sh
```

浏览器自动打开 `http://localhost:8800`。你会看到一辆车在 4 车道直路上自己开。

**做三个观察**（做完再继续读）：

1. 找速度曲线：车不是一下子冲到目标速度的——它在「加速 → 松油 → 稳住」。这是
   纵向控制（油门/刹车）在起作用。
2. 找一个红灯或慢车：观察车怎么减速、停车、再起步。**注意它的减速是渐进的，
   不是瞬间刹停**。
3. 切到 2D 俯视图：看那条绿色轨迹——那就是 `step_bicycle` 一步步积分出来的位置
   序列。

## 问题浮出水面：一辆会开的车，还不是一辆「会自己开」的车

到现在，你有了一辆「会开」的车：给它油门/刹车/方向盘，它就能往前跑。但等一下——
**谁给它油门？谁给它刹车？**

在 `demo.sh` 里，是整套系统在「开」它。而这引出了全书最重要的结构性问题：

> 一辆车要「自己开」，必须形成一个**闭环**：
> 车现在在哪（感知）→ 该往哪去、该不该停（决策）→ 怎么执行（控制）→ 执行完再
> 感知……如此循环。

而这个闭环里的每一步，都需要「人」——不是开车的人，而是**写代码的人**。你需要：

- 一个模块负责「看」（感知：前车在 30 米外）；
- 一个模块负责「想」（决策：前车太慢，我要变道）；
- 一个模块负责「做」（控制：打 0.05 弧度方向盘，油门 30%）；
- 一个模块负责「兜底」（安全：离前车太近，立即刹车）。

这就是为什么系统最终有 15 个节点，而不是一个大程序——**一个模块一件事，边界清晰，
坏了好查**。这也是为什么下一卷要先讲「15 个模块怎么互相说话」：因为有了分工，
就有了通信的问题。

## 小结

这一章你只学会了一件事，但它是最重要的一件：**自动驾驶的地基不是深度学习，是
运动学。** 一辆车怎么动，由三个输入（油门/刹车/方向盘）和车的几何（轴距）决定，
用这个公式描述：

```
yaw_rate = (v / wheelbase) · tan(steer)     ← 车怎么转弯
```

你亲手跑了一辆车，观察了它的加速、减速、停车。你发现了关键问题：**车会动 ≠ 车会
自己动**。要让它「自己动」，需要一整套闭环：感知、决策、控制、安全。
