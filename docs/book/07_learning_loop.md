# 卷七 · 第七课：让车学会自己开

## 本章问题

到目前为止，你的车是**被代码开着**的：决策层的状态机、规划层的轨迹、控制层的 PID，
都是人写的规则。但人写的规则有天花板——你不可能把「每个路口该怎么让行」都写成规则。

这一章的问题：**怎么让车自己学会开？** 不是人写规则，而是让车**从数据里学**。

## 你自己的答案：把模型直接接上方向盘

最朴素的想法：拿一堆「人怎么开车」的数据训练一个神经网络，然后把网络的输出直接
接上油门和方向盘。

```python
# 训练：输入状态，输出动作
model.fit(states, actions)

# 部署：网络输出 = 控制指令
throttle, steer = model.predict(current_state)
apply(throttle, steer)
```

看，一条直路。但**在你把这条代码上车之前，先想清楚一个问题**：

> 如果模型学歪了——比如它学会了「看到行人就加速」（训练数据里恰好有几次这样的噪声），
> 你把它直接接上方向盘，会发生什么？

答案：**当场撞人。** 而且更糟：你不会提前知道它学歪了，因为「学歪了」和「没学歪」
在训练曲线上一模一样（loss 都挺低）。**直接把模型接上方向盘，等于把「模型的错误」
和「车的安全」绑在一起——这是新手犯的第一个致命错误。**

## 一个关键洞察：模型的错误，不该直接影响车

正确的做法，是把模型的错误和车的安全**隔离开**。怎么隔离？思路是：**先让模型在
旁边「看」，看它学得对不对；确认它学对了，才让它「开」。**

这就是**影子模式（shadow mode）**：

```
        ┌─────────────────────────────────┐
真实控制：  人写的规则 → 规划 → 控制 → 车   ← 车一直由它开（安全）
        └─────────────────────────────────┘
        ┌─────────────────────────────────┐
影子模型：  模型 → 预测动作 → 只记录，不执行  ← 模型在旁"看"（怎么错都不影响车）
        └─────────────────────────────────┘
           对比：模型预测 vs 真实执行 → 算偏差 → 决定要不要让它上场
```

**影子模式的两条铁律**：

1. 模型的输出**绝不接入**控制链——哪怕它是随机权重，车也照常安全行驶；
2. 模型好不好，靠**对比**——模型预测的动作 vs 规则实际执行的动作，偏差小才有资格
   上场。

这就是卷三那条「模型是乘客，不是驾驶员」的落地。**先看，再评，最后才上场。**

## 四阶段闭环：从数据到上场的完整旅程

项目的车端学习闭环分四阶段，对应四个节点：

```
Stage 0  data_recorder  采集：把「规则开车」的样子录下来（状态 + 动作 = 样本）
Stage 2  inference      影子推理：模型在旁预测，只记录不执行
Stage 3  learner        车端微调（可选）：在车上继续学
Stage 4  model_ota      OTA：新模型热替换、A-B 对比、回滚
```

### 阶段 0：采集——你要学谁的驾驶？

行为克隆（BC）的「老师」是**当前的规则系统**。车每开一帧，`data_recorder` 记下一行
样本：

```
{特征（这帧车看到了什么）, 动作（规则系统这帧做了什么）}
```

**样本 = 特征 + 标签**。特征通常是 23 维（定位、障碍物、行为状态），标签是动作
（5 维）。一句话：**你采集的是「规则开车的录像」，模型要学的是从录像里学会开车。**

**为什么学规则而不学人类？** 因为规则系统**可复现**——同一帧，规则永远给同样的动作，
样本没有噪声。人类开车则不可复现。**学一个确定性的老师，比学一个随机的老师容易得多。**

### 阶段 2：影子推理——模型开始"看"

训练完之后，模型以 `inference` 节点的身份上线——但**只发布 `inference/trajectory`
供对比，绝不接入控制**。它和规则系统同时开车，你看两条轨迹差多少。

### 阶段 3→4：晋级与 OTA——模型"上场"

只有当影子评估证明「模型和规则几乎一样好（甚至更好）」时，才允许晋级。晋级后通过
`model_ota` 热替换——注意 OTA 也支持**回滚**：新模型一上场就表现糟糕，一键切回旧版。

**为什么 OTA 必须支持回滚？** 因为「影子评估通过」不代表「真车一定好」——你永远无法
在仿真里穷尽所有情况。**回滚是「评估错了」的后悔药。** 没有回滚的 OTA，等于一次豪赌。

## 评估 = 回报：你已经在用强化学习的地基了

这里有一个值得记住的洞察：你评估模型好不好，用什么标准？——碰撞？偏航？停滞？

而这些标准，项目**早就有**：`demo_evaluator` 的评分（卷九）就是——碰撞计分、偏航计分、
停滞计分。**评估器的分数，就是模型的「回报」**——这正是强化学习的回报信号。你不需要
另造一套评估体系，评估器已经在 `/tmp/flow_topology.json` 里给你算好了。

## 一个诚实的提醒：行为克隆的天花板

行为克隆有一个著名缺陷（DAgger 论文的核心论点）：**分布漂移**。

- 规则系统（老师）只在「它擅长」的场景里开得好；
- 模型（学生）一开始学的是老师的「样子」；
- 一旦模型偏离了老师的轨迹，它就进入了**老师没示范过的地带**——那里老师没教过，
  模型只能瞎猜；
- 越猜越偏，越偏越猜——**越开越歪**。

治它的办法（DAgger）：让模型也去开（在仿真里），把「模型开歪的地方」补记成新样本，
让老师在这些歪的地方重新示范。**这就是「自我对弈」：模型越开越好的过程，也是数据
越来越针对弱点的过程。**

## 动手实践

```bash
# 1. 跑一遍完整闭环（采集 → 训练 → 影子评估 → 晋级）
python3 ci/train_pipeline.py

# 2. 只做影子评估（不采集、不训练）
python3 ci/train_pipeline.py --shadow-only

# 3. 看推理节点的影子轨迹（在 FlowBoard 上对比两条轨迹：规则 vs 模型）
```

**观察**：影子模式下，模型预测的轨迹和规则执行的轨迹，大部分重叠，偶尔偏离。那些
「偏离」的地方，就是模型还没学会的地方——也是「该继续采集」的信号。

## 小结

这一章你学会了让车学习，但更重要的是学会了**学习的正确姿势**：

- **致命错误**：把模型直接接方向盘 = 把模型的错误和车的安全绑在一起。
- **影子模式**：模型先旁路「看」，评估通过才「开」——错误不影响安全。
- **四阶段闭环**：采集（学规则的录像）→ 影子推理（旁路对比）→ 晋级 → OTA（可回滚）。
- **评估器分数就是 RL 回报**：你不需要另造评估体系。
- **行为克隆的天花板**：分布漂移——越开越歪，用 DAgger 自我对弈治。
