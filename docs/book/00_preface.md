# 前言：这本书教你造一辆会自己开的车

## 这本书不是什么

先说我**不**打算做什么。市面上讲自动驾驶的书，大多是「产品说明书」：打开第一页，
一张架构图，十五个方块，每个方块下面写着「负责感知」「负责规划」，翻到最后，
你记住了一堆名词，但**你还是不知道这些方块是怎么造出来的**。

这本书不是那种书。

也不是「论文集」——不会堆公式让你推导。也不是「API 手册」——不会罗列函数签名。
这是一本**手把手的建造指南**：你从第一行代码开始，亲手把一个能跑的自动驾驶中间件
搭起来，每一层都理解「为什么是它」。

## 这本书是什么

这本书教你**从零把一个自动驾驶中间件造出来**——不是照抄，而是让你理解每一个
设计决策「为什么是它」：

- 为什么节点之间要用「发布/订阅」而不是函数调用？
- 为什么消息队列要存指针而不是存 64KB 的消息体？
- 为什么车辆模型要用「中心参考点」而不是「后轴参考点」？
- 为什么规划层必须是「速度与轨迹的唯一权威」？
- 为什么安全层永远不许理解「任务意图」？

这些问题没有一个是「想当然」。它们每一个，都是有人在某个深夜，看着一辆车以错误的
方式开走，然后才明白的。

这本书的写法是**问题驱动**的。每一章都从一个问题开始，给你一个「你自己会先想到的
简单答案」，然后让你看到那个答案在真实世界里怎么崩塌，最后把你带到项目真正采用的
方案面前——并且告诉你，这个方案下一次会在哪里崩塌。

## 项目定位

KunAutoDrive是一个**仿真优先的自动驾驶中间件**。它的核心是一个
Pub/Sub 消息总线 + 调度器 + 传输层，上面跑着 15+ 个协作节点（感知、融合、规划、
控制、安全、仿真、可视化……）。

**它不是**：
- 一个自动驾驶产品（没有量产承诺）
- 一个仿真器（FlowSim 是它的仿真模块，不是独立产品）
- 一个 ROS 替代品（它解决的是不同层级的问题）

**它是**：
- 一个**可运行的实验平台**：改一行代码，45 秒内看到效果
- 一个**学习工具**：每一层都有对应的教程和可交互的 3D 仪表盘
- 一个**算法验证框架**：Python 仿真先行 → C++ 移植 → 自动回归评分

### 与业界方案的对比

| 维度 | ROS 2 | KunAutoDrive |
|------|-------|-------------|
| 定位 | 通用机器人中间件 | 自动驾驶专用中间件 |
| 消息模型 | DDS / topic | 进程内 Pub/Sub + IPC/TCP |
| 调度 | executor（回调式） | FlowCoro 混合调度器（时序与拓扑可控） |
| 仿真 | gazebo / carla（外部） | FlowSim（内建，同进程） |
| 可视化 | rviz2（外部） | FlowBoard（内建 3D 仪表盘） |
| 学习闭环 | 需自行搭建 | 内建 data_recorder → inference → learner → OTA |
| 代码量 | 数十万行（核心） | ~12 万行（全栈） |

KunAutoDrive 选择了「小而全」——把自动驾驶的每一层都实现一遍，让你理解全貌。
生产部署时，你可以把任何一层替换成工业级实现。

## 为什么敢这么写

因为这本书写的不是一个纸上的架构，而是一个**真的能跑的系统**。作者为它写了十几万行
代码，跑了上千次演示，修过几十个「看起来不可能」的 bug。这里讲的每一个「为什么」，
背后都有一次真实的翻车记录。你在这本书里看到的每一段代码，都是当前仓库里真实存在、
真实运行着的代码——不是 PPT 上的伪代码。

## 给读者

### 你需要什么

你不需要懂自动驾驶。你需要的是：

- 会读 C 和 C++（不会也没关系，每段代码都讲得很慢）；
- 会打开终端，会敲 `cmake`、`git` 这类命令；
- 一个 Linux 或 macOS 环境；
- 以及最重要的——**愿意动手**。

### 你是谁

这本书为三类读者设计：

**学习者**（研究生/自学者）：从头到尾按顺序读，每一章都跑一遍。10 周完成，
你会对自动驾驶全栈有扎实的理解。

**工程师**（转行/入职）：先读卷一~卷三搭环境和理解架构，然后按需跳到感兴趣的卷。
附录的 [INDEX.md](../INDEX.md) 和 [GLOSSARY.md](../GLOSSARY.md) 可以快速查术语。

**研究者**（算法验证）：直接跳到卷三（算法）和卷七（学习闭环），用 Python 仿真
工具快速验证你的想法，再决定是否移植到 C++。

学完这本书，你会亲手（在指导下）经历以下每一件事：

## 怎么用这本书

### 每章结构

每一章的结构都一样，你很快会习惯：

```
┌─ 本章问题：这一章要解决一个什么问题
├─ 你自己的答案：如果是你，你会怎么写（先别翻下文，想想）
├─ 为什么不够：这个朴素答案在真实世界里怎么失败
├─ 真正的方案：项目怎么做的（附真实代码，逐行讲）
├─ 动手实践：跑起来，改一改，看它怎么坏
├─ 深入原理：算法/协议/数据结构的底层细节
├─ 常见陷阱：真实踩过的坑和解决方案
└─ 小结：你学到了什么，下一章要解决什么
```

「你自己的答案」那一节最重要。**先想，再看答案。** 直接翻到方案，你记住的是结论；
先自己想过，你记住的是「为什么」。

## 关于项目名称

**Kun（鲲 / 坤）** ——「鲲」是乘风破浪、展翅千里的志向；「坤」是八卦里的地，代表厚德载物与承载顺应。自动驾驶中间件就是
「承载」算法和传感器的那层——它不该抢算法的活（那是越界），也不该让用户感知到
它的存在（好的中间件是透明的）。

**AutoDrive / Flow** —— 消息「流动」的自驾引擎。数据从传感器流到决策，从决策流到执行，
从执行流到反馈。好的消息总线就像好的水管：你只看到水龙头出水，从不关心管子。
