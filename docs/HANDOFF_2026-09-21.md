### P0 #1 — `min_road_margin_m` 4.325→0.789 真实原因（无 commit）

诊断结论：**不是 driving regression，是测量窗口/采样位置切换**。

| Baseline | min_road_margin | min_road_margin_at_s | 几何含义 |
|----------|-----------------|----------------------|---------|
| 旧 (52b45e8, 2026-08-25) | 4.325m | 5.53s（掉头中） | 掉头穿越道路中心时大 |signed_offset| 反而远离车道边缘 |
| 新 (f5619a6, 2026-09-20) | 0.785m | 27.1s（巡航段） | 外车道中心（signed_offset=5.22m），正常巡航位 |

公式：`margin = 7.0 - |signed_offset| - 1.0`（4 车道 road_center_y ±7m，半宽 3.5m × 2）。

- `|signed_offset|=5.22m` 是外车道中心，几何合法
- `road departure` FAIL 条件（`< -1.5m` 或连续 ≥10 帧 `<0`）永不触发
- `min_ratio 0.4` → 下限 0.32m，0.785m 在容差内
- 复跑稳定 0.74-0.79m，但每次 7-9 场景取原值有 ±0.15m 噪声

**建议**：保留当前 baseline，metric 留作噪声监测而非回归拦截。

## 3. 已完成 — P1 五项

### P1 #4 — ltv_mpc.c Riccati p 递推 + KKT 单测 ✅ `0f44118`

**handoff §4.4 控制 W1 修复**：`ltv_mpc.c:245-260` 的 p 递推有 3 处错：
1. 用刚被覆盖的 `solver->P`（=P_k）当作 P_{k+1}
2. 漏 + p_{k+1}（affine 累积项）
3. 多加 `K'R·kff`（标准递推不含此项）

kappa≠0 场景修前 u[0]=0.00750 vs 精确解 0.04345（5.8× 偏差）。`use_ltv_mpc` 默认 0 → 潜伏地雷。

**修复**：在 memcpy(solver->P, P_new) 前保存 `P_old = P_{k+1}` / `p_old = p_{k+1}`，P_new 的 AtPA 也用 P_old，p 更新用 `P_old * c + p_old`，删除 K'R·kff。

**回归保护** `modules/adas_nodes/test_ltv_mpc.c`：5 个用例，参考值用纯 Python 标准 affine-LQR Riccati 算出（无 numpy 依赖），容差 1e-9。临时回退 fix 跑测试 → 3/21 FAIL，确认测试真的能拦 bug。`add_test(NAME ltv_mpc_kkt ...)` 顶层 ctest 29/29 通过。

### P1 #5 — planning valid=0 走 park 兜底 ✅ `58bda1e`

### P1 #6 — safety_control 制动距离模型 + hysteresis ✅ `43fc4e7`

### P1 #8 — sensor_model 真点云（射线投射+距离噪声+丢失率） ✅ `e86ea5b`

**handoff §4.3 仿真感知自证闭环修复（producer 侧）**：原 `sensor_model` 把 ego 自己的带噪位置当 `sensor/lidar` 发布（`lidar.x = ego_x + noise`），`perception_node` 反而写死 24 个地面环 + 8×N 点 → DBSCAN 重新聚回 → `fusion_node` 注释直书 lidar 位置真值。整个链路在「模拟传感器」不是「模拟物理」。

**本 PR 是 producer 侧基建**：mode=1 启用真点云路径，发布 `sensor/lidar_points` JSON 数组：
- 64 根方位射线等分 FOV
- 每根与 obstacle AABB 求最近 hit（`ray_aabb_t`）
- 命中点沿射线方向叠加 σ=α·range 高斯噪声（距离越远噪声越大）
- 固定 5% 丢失率（`rand_uniform_01 < 0.05` 跳过射线，模拟空气/遮挡）
- intensity = `exp(-range/30)`（30m 半衰期 ≈ exp(-1)≈0.37，贴近真实 LiDAR）

**默认 mode=0**（保持旧 LidarFrame 行为不变，向后兼容）；启用方式：pipeline.json params 加 `"lidar_mode":1`。

**新增**：4 个静态函数（`rand_uniform_01`, `rand_gauss`（Box-Muller）, `ray_aabb_t`, `publish_raycast_points`）；`sensor/lidar_points` 加入 `s_outputs[]`（type_id=0 ad-hoc，cJSON JSON 数组）；pipeline.json + pipeline_windows.json 加 `sensor/lidar_points` JSON type publish。
